# Pulsio Analytics Data and User Tracking Specification

Implement the following changes.

All database changes must be applied directly to `../packages/api/dao/schema.sql` and `packages/api/dao/clickhouse.sql`. Do not create migrations. The production database will be reset and restarted manually.

## PostgreSQL IDs

- Use PostgreSQL 18 native UUIDv7 for every PostgreSQL UUID primary key.
- Update `../packages/api/dao/schema.sql` so every UUID primary key has `default uuidv7()`.
- Keep UUIDv7 as the canonical database ID.
- Remove application-side `randomUUID()` generation for PostgreSQL primary-key inserts. Let PostgreSQL assign the ID.
- When an insert needs its generated ID for dependent inserts, use `returning` and pass the returned ID.
- Keep `created_at` next to each `id` column as the authoritative creation timestamp. UUIDv7 order is not strictly chronological across servers.

## One Tracking Snippet per User

### Goal

A user uses one immutable Pulsio identifier in its tracking snippet. The same snippet must track events from every domain where the user installs it. Pulsio must automatically create a tracked-domain record when it receives a valid event from a new hostname.

The domain entered during registration is only the first tracked domain. It is not the snippet identifier.

### Identifier

Use `users.id` as the public Pulsio identifier.

```html
<script async src="https://api.pulsio.io/client.js" data-pulsio-id="<users.id>"></script>
```

`data-pulsio-id` is public. It identifies the analytics user and is not an authentication secret. Do not use `sites.id` or a domain in the snippet.

### Data Model

Keep the existing `sites` table. A row represents one tracked hostname within a user.

```text
users
  id

sites
  id
  user_id
  domain
  detected_at
```

- `sites.user_id` references the user identified by `data-pulsio-id`.
- `sites.domain` is a normalized hostname.
- A hostname must be unique globally. It can belong to only one user.
- Registration creates the first `sites` row from the submitted domain.
- New hostnames are created automatically when an event is received for the user.
- `events.site_id` continues to reference the matching `sites.id`.
- Do not add a `primary_domain` column.

### Tracker

Update `../packages/api/client/client.ts`.

- Read `data-pulsio-id`.
- Select the script with `script[data-pulsio-id]`.
- Do not read or send `data-site`.
- Send the user ID in the event field currently named `s`.
- Keep the payload size limit and all existing tracking behavior unchanged.
- If `data-pulsio-id` is absent, do not send events.

### Event API Contract

`TrackEvent.s` means the Pulsio user ID and must validate as a UUID.

For each event:

1. Normalize the hostname from `data.u`.
2. Resolve the user from `data.s`.
3. Reject the event if the user does not exist or is suspended.
4. Find `sites` by `{ user_id, domain }`.
5. If it exists, use it.
6. If it does not exist, insert it and use the UUIDv7 generated by PostgreSQL.
7. Store the event using the resolved or created `sites.id`.
8. Set `detected_at` on that site.

Do not compare the event identifier with a domain or `sites.id`.

### Domain Normalization and Security

Use the same normalization for registration and automatic discovery:

- Parse a URL or hostname.
- Lowercase it.
- Remove a leading `www.`.
- Remove port, path, query, fragment, credentials, and protocol.
- Reject invalid hostnames.

A hostname already assigned to another user must not be reassigned. Reject that event and do not create a duplicate domain record.

A public snippet identifier can be copied to another website. Pulsio cannot automatically prove that a newly discovered domain belongs to the user. For this iteration:

- Track automatically discovered domains.
- Clearly label them as automatically discovered in the dashboard or setup response.
- Do not add domain verification, allow lists, or secret tracker tokens.

The event URL hostname is the source of truth for the stored domain. Use the HTTP `Origin` header only as an additional consistency check when it is present, not as the only source.

### API and UI

- Return the same user-level snippet for every site in user setup responses.
- The registration setup page must display the user-level snippet.
- Keep existing per-domain site selection and analytics behavior.
- A newly discovered hostname must appear in the user site list without manual creation.
- Update setup text that says the snippet must match the entered domain.

## Plans

### Data Model

Add `plans` table.

```text
plans
  id
  name
  monthly_price
  yearly_price
  valid_from
```

- `plans.name` accepts only `start`, `grow`, `scale`, or `expand`.
- `plans.monthly_price` stores monthly price as raw numeric amount.
- `plans.yearly_price` stores yearly price as raw numeric amount.
- `plans.valid_from` stores date and time when plan replaces previous version with same `name` in pricing API response.
- Do not store plan descriptions or feature details in database.

### API and Website

- Add public API endpoint that returns current price for each plan.
- API selects one current row per `plans.name`: latest `valid_from` that is not after current time.
- API returns raw numeric monthly and yearly prices. Website formats currency and amounts.
- Website keeps plan names, descriptions, feature details, and display order hardcoded.
- Website retrieves only plan prices from API.

## ClickHouse Events

- Remove the event-level `id UUID` column from `../packages/api/dao/clickhouse.sql`, event types, and ingestion.
- Do not use an event UUID as part of the ClickHouse sort key.
- Use `MergeTree`, monthly partitioning, and an analytics-oriented sort key.
- Keep a three-year TTL for events.

Use these timestamp definitions:

```sql
timestamp DateTime64(3, 'UTC') CODEC(Delta(8), LZ4),
created_at DateTime64(3, 'UTC') DEFAULT now64(3) CODEC(Delta(8), LZ4)
```

```sql
PARTITION BY toYYYYMM(timestamp)
ORDER BY (site_id, timestamp, event_name, fingerprint)
TTL toDateTime(timestamp) + INTERVAL 3 YEAR DELETE
```

Add these event columns and populate them during ingestion:

```sql
utm_source String DEFAULT '',
utm_medium LowCardinality(String) DEFAULT '',
utm_campaign String DEFAULT '',
utm_content String DEFAULT '',
utm_term String DEFAULT '',
referrer_source String DEFAULT '',
country_code FixedString(2) DEFAULT '',
subdivision_code LowCardinality(String) DEFAULT '',
locality LowCardinality(String) DEFAULT ''
```

- Store each UTM field separately instead of parsing `url` during analytics queries.
- Keep `source` and `channel` as normalized reporting dimensions.
- Set `referrer_source` to the normalized external referrer host. Keep the full `referrer` unchanged.
- Obtain `country_code`, `subdivision_code`, and `locality` from GeoLite data. Keep existing display-name columns during this change.
- Do not add raw advertising click IDs. If required later, add only a non-identifying click-ID type or presence flag.
- Do not add persistent `session_id` or `user_id` columns. Keep the existing privacy-preserving fingerprint and query-time sessionization.

## Revenue Reporting Currency

- Keep event `revenue_amount` and `revenue_currency` as the original transaction amount and ISO 4217 currency.
- Do not store `revenue_reporting_amount` or `revenue_reporting_currency` in ClickHouse. The reporting currency is selected by the user for each analytics request.
- Add a validated `reporting_currency` analytics request parameter. Default it to `USD`.
- Convert aggregated revenue at query time using the UTC date of each event. Cache required exchange rates by date and currency indefinitely.
- Retrieve USD-based historical rates from `https://api.frankfurter.dev/v2/rates?base=usd&date={event_date}`.
- For a source currency other than USD, convert with `amount / usd_to_source_rate * usd_to_reporting_rate`. Treat the USD rate as `1`.
- Use the rate returned for the event date. Historical reports must return the same converted totals on later executions.

## Query, Type, and Test Updates

- Update shared event Zod schemas, API validation, enrichment, ClickHouse insert payloads, and tests for the new fields and removed event ID.
- Update analytics queries to use persisted UTM columns instead of `extractURLParameter(entry_url, ...)`.
- Preserve current dashboard results for sources, channels, visits, bounce rate, duration, funnels, goals, and revenue.
- Add or update integration tests for the following behavior:
  1. A registration response contains `data-pulsio-id="<user.id>"`.
  2. The first registered domain accepts events using the user ID.
  3. An event from a new hostname with the same user ID creates a `sites` row and is accepted.
  4. Events from both domains are stored under different `events.site_id` values.
  5. An unknown user ID is rejected.
  6. A domain owned by another user is rejected and is not reassigned.
  7. A domain value or `sites.id` used as `s` is rejected.
  8. Normalization makes `www.example.com` and `example.com` resolve to one hostname.

## Out of Scope

- Multiple tracked identities per user.
- Site-level snippet IDs.
- Domain ownership verification.
- Merging domains across users.
- Aggregated user-level analytics queries.
