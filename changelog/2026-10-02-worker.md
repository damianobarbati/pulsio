## Event ingestion

- `POST /event` accepts `event_id` and `timestamp` from request payload.
- API validates user and domain, then creates the event row.
- API runs `SET event:{event_id} 1 NX EX 3600` in Redis.
- Existing key: return `event_id` without error and without enqueueing.
- New key: add event row to Redis Stream with `XADD`.
- Redis failure returns HTTP error.
- Event is not written to ClickHouse by API.
- Event loss between `SET NX` and `XADD` is accepted.

## Worker

- Worker continuously processes the Redis Stream.
- Read available messages in batches.
- Insert each batch into ClickHouse with `EventRepository.createAll`.
- Acknowledge messages only after successful ClickHouse insert.
- Keep unacknowledged messages available for retry.
- When no message is available, sleep 100 ms and retry.
- `BATCH_SIZE` defines maximum batch size.
- Do not use consumer groups or Lua scripts.

## Deduplication

- Redis marker TTL is 1 hour.
- Duplicate `event_id` received within TTL is discarded silently.
- Duplicate events after TTL are accepted.
- Redis `SET NX` is the only deduplication check.
- No ClickHouse lookup is required for deduplication.

## Performance

- Event latency is `created_at - timestamp`.
- Measure Redis enqueue, worker processing, ClickHouse insert, and ClickHouse visibility.
- Run progressive load tests and record throughput, latency, errors, missing events, and duplicates.
- Monitor Redis memory usage and adjust TTL accordingly.
